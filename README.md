# HD Wallet Explorer

Локальный open-source инструмент для просмотра HD-кошельков, генерации адресов и проверки публичной активности.

Текущая версия: **v0.8.0**  
Лицензия: **MIT**

> Проект находится в ранней версии. Не используйте seed-фразу от кошелька с реальными средствами до независимого аудита кода.

## Возможности

- Ethereum offline-деривация по пути `m/44'/60'/0'/0/N`.
- Bitcoin mainnet/testnet.
- Bitcoin Legacy BIP44, Nested SegWit BIP49, Native SegWit BIP84 и Taproot BIP86.
- Получение одного адреса или диапазона адресов.
- Отображение public key, private key и WIF в локальном режиме.
- Сетевой сканер публичных Bitcoin- и Ethereum-адресов.
- Gap limit, таймауты, повторные запросы, задержка между запросами и остановка сканирования.
- Watch-only режим без seed-фразы и приватных ключей.
- Импорт `xpub`, `ypub`, `zpub`, `tpub`, `upub`, `vpub`.
- Discovery Engine v1 для веток External и Change.
- Сохранение публичных watch-only профилей в `localStorage`.
- Экспорт результатов в CSV и JSON.

## Запуск

Требуется Node.js 22 или новее.

```bash
npm install
npm run dev
```

Откройте:

```text
http://localhost:3000
```

Полная проверка проекта:

```bash
npm run check
```

Команда последовательно запускает TypeScript typecheck, ESLint, тесты и production build.

# Как пользоваться

В приложении есть два основных режима:

1. **Seed / BIP39** — работа с мнемонической фразой.
2. **Watch-only** — работа только с расширенным публичным ключом.

Для проверки интерфейса используйте встроенную демо-фразу. Реальную seed-фразу вводите только на доверенном офлайн-устройстве.

## 1. Получение одного адреса из seed-фразы

### Ethereum

1. Откройте вкладку **Seed / BIP39**.
2. Выберите **Ethereum**.
3. Выберите режим **Один адрес**.
4. Укажите `Address index`.
5. Введите BIP39 mnemonic.
6. При необходимости укажите BIP39 passphrase.
7. Нажмите **Получить адрес**.

Используется путь:

```text
m/44'/60'/0'/0/N
```

Результат содержит:

- Ethereum address;
- public key;
- private key.

Приватный ключ скрыт до нажатия отдельной кнопки.

### Bitcoin

1. Откройте вкладку **Seed / BIP39**.
2. Выберите **Bitcoin**.
3. Выберите сеть: `Mainnet` или `Testnet`.
4. Выберите тип адреса:
   - Legacy · BIP44;
   - Nested SegWit · BIP49;
   - Native SegWit · BIP84;
   - Taproot · BIP86.
5. Выберите режим **Один адрес**.
6. Укажите:
   - `Account`;
   - `External / 0` или `Change / 1`;
   - `Address index`.
7. Введите mnemonic и при необходимости passphrase.
8. Нажмите **Получить адрес**.

Результат содержит:

- Bitcoin address;
- public key;
- private key;
- WIF.

Приватный ключ и WIF скрыты до явного открытия.

## 2. Генерация диапазона адресов

1. Выберите Ethereum или Bitcoin.
2. Откройте режим **Диапазон и сканер**.
3. Укажите начальный индекс.
4. Укажите количество адресов.
5. Для Bitcoin дополнительно выберите account и ветку.
6. Введите mnemonic.
7. Нажмите **1. Сформировать диапазон**.

После генерации появится таблица с:

- индексом;
- derivation path;
- адресом;
- public key;
- кнопкой копирования.

Результат можно сохранить в CSV или JSON.

## 3. Сканирование адресов из seed-фразы

После формирования диапазона откроется блок сетевого сканера.

### Bitcoin

По умолчанию используются Esplora-compatible endpoint:

```text
Mainnet: https://mempool.space/api
Testnet: https://mempool.space/testnet/api
```

Порядок работы:

1. Проверьте endpoint.
2. Укажите `Gap limit`.
3. При необходимости настройте:
   - количество повторных попыток;
   - таймаут запроса;
   - паузу между адресами.
4. Поставьте флажок разрешения отправки публичных адресов в API.
5. Нажмите **Запустить сканер**.

Сканер покажет:

- баланс каждого адреса;
- количество транзакций;
- статус `Использован`, `Пустой` или `Ошибка`;
- общий прогресс;
- число проверенных адресов;
- число использованных адресов;
- число ошибок.

Сканирование можно остановить кнопкой **Остановить**.

### Ethereum

Для Ethereum требуется JSON-RPC endpoint с поддержкой CORS.

Пример формата:

```text
https://your-ethereum-rpc.example
```

Сканер вызывает:

- `eth_getBalance`;
- `eth_getTransactionCount`.

Публичный RPC может иметь ограничения по частоте запросов. При ошибках увеличьте задержку между запросами или используйте собственный RPC.

# Watch-only

Watch-only режим позволяет получать и сканировать Bitcoin-адреса без mnemonic, seed и приватных ключей.

Поддерживаются:

| Ключ | Сеть | Тип адреса |
|---|---|---|
| `xpub` | Mainnet | Legacy |
| `ypub` | Mainnet | Nested SegWit |
| `zpub` | Mainnet | Native SegWit |
| `tpub` | Testnet | Legacy |
| `upub` | Testnet | Nested SegWit |
| `vpub` | Testnet | Native SegWit |

## 4. Генерация watch-only адресов

1. Откройте вкладку **Watch-only**.
2. Вставьте account-level расширенный публичный ключ.
3. Убедитесь, что приложение правильно распознало:
   - префикс;
   - сеть;
   - тип адреса;
   - depth.
4. Выберите ветку:
   - `External / 0` — адреса получения;
   - `Change / 1` — адреса сдачи.
5. Укажите начальный индекс.
6. Укажите количество адресов.
7. Нажмите **Сформировать адреса**.

Приватные ключи в этом режиме отсутствуют и не могут быть восстановлены из xpub.

## 5. Сохранение watch-only профиля

1. Введите публичный ключ.
2. Укажите понятное имя, например `Ledger Bitcoin`.
3. Нажмите **Сохранить публичный профиль**.

Профиль сохраняется только в `localStorage` текущего браузера и содержит:

- имя;
- extended public key;
- дату создания.

Seed, mnemonic, passphrase и private key не сохраняются.

Очистка данных браузера удалит сохранённые профили.

## 6. Watch-only Discovery Engine

Discovery Engine автоматически проверяет обе ветки account-level публичного ключа:

```text
External / 0
Change / 1
```

Параметры:

- **Address gap** — количество пустых адресов подряд, после которого текущая ветка считается законченной;
- **Максимум адресов на ветку** — защитный верхний предел;
- **Esplora API** — endpoint для проверки Bitcoin-адресов.

Порядок работы:

1. Вставьте xpub/ypub/zpub либо тестовый эквивалент.
2. Перейдите к Discovery Engine.
3. Проверьте Esplora endpoint.
4. Укажите Address gap, обычно `20`.
5. Укажите максимальное количество адресов на ветку.
6. Разрешите сетевые запросы.
7. Нажмите **Запустить discovery**.

Discovery последовательно:

1. проверяет External;
2. останавливается после достижения Address gap либо верхнего предела;
3. проверяет Change;
4. формирует общую сводку.

В результате отображаются:

- проверенные адреса;
- использованные адреса;
- баланс;
- число транзакций;
- ошибки;
- отдельная статистика External и Change.

## Ограничение multi-account discovery

Account-level xpub не позволяет получить соседние аккаунты:

```text
account 0
account 1
account 2
```

Причина: уровень account в BIP44 является hardened. Из публичного ключа account 0 нельзя вывести account 1.

Для проверки нескольких аккаунтов нужны:

- отдельный xpub каждого аккаунта;
- либо wallet descriptor;
- либо mnemonic, из которой аккаунты выводятся локально.

## Taproot watch-only

Taproot BIP86 watch-only пока не включён.

Обычный `xpub` сам по себе не сообщает, что его нужно интерпретировать как BIP86 Taproot, а не как Legacy. Для безопасной реализации требуется явный выбор политики или импорт descriptor.

# Безопасность

- Вся криптографическая деривация выполняется в браузере.
- Серверная часть отсутствует.
- Аналитика и cookies отсутствуют.
- Сетевой режим выключен по умолчанию.
- В API отправляются только уже сформированные публичные адреса.
- Mnemonic, passphrase, seed, private key и WIF не отправляются в сеть.
- Для внешних endpoint разрешён только HTTPS.
- HTTP разрешён только для `localhost`, `127.0.0.1` и `::1`.
- URL с логином или паролем отклоняются.

Использование публичного API раскрывает оператору API набор проверяемых адресов и ваш IP-адрес. Для большей конфиденциальности используйте собственный Bitcoin Esplora или Ethereum RPC через localhost.

## Рекомендуемый безопасный порядок

Для просмотра реального кошелька предпочтительно:

1. получить account-level xpub на аппаратном кошельке;
2. перенести только xpub на компьютер;
3. использовать вкладку Watch-only;
4. не вводить рабочую seed-фразу в браузер.
